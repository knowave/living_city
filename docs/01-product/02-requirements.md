### 2.1 초기 세계

| 항목 | 기본값 |
|---|---|
| 세계 수 | 사용자당 1개부터 시작 |
| 초기 인구 | 성인 시민 100명 |
| 초기 기업 | 10개 |
| 정부 | 1개 |
| 소득세율 | 15% |
| 초기 맵 | 64 × 64 타일 |
| 성능 검증용 맵 | 512 × 512 타일 |
| 타일 크기 | 64 × 32px |
| Chunk 크기 | 32 × 32 타일 |
| 초기 시간 단위 | 1 Tick = 시뮬레이션 1시간 (하루 = 24 Tick) |
| 시간 배율 | 정지, 1배속, 4배속, 16배속 |
| 1배속 기준 | 현실 2초 = 시뮬레이션 1일(24 Tick), Tick 간격 약 83ms |

시뮬레이션의 월은 30일, 연도는 12개월인 가상 달력으로 단순화한다.

### 11.1 성능

- 최초 목표: 시민 100명, 기업 10개
- 렌더링 목표: 데스크톱 1080p 환경에서 60FPS
- 초기 맵: 64 × 64 타일
- 확장 검증: 512 × 512 타일
- 시뮬레이션: 1 Tick 처리 시간이 설정된 실시간 Tick 간격을 지속적으로 초과하지 않을 것
- SSE: 매 프레임이 아닌 변경 이벤트와 집계 상태 중심

성능 수치는 목표이며 실제 기기와 데이터에 대한 벤치마크가 필요하다.

### 11.2 안정성

- 세계별 중복 Runner 실행 방지
- 동일 명령 중복 실행 방지
- Tick 원자성 보장
- 이벤트 전달 실패 시 복구
- SSE 연결 종료 시 자원 정리
- 느린 구독자의 대기열 크기 제한
- 경제 원장의 자금 보존 검증

## 13. MVP 출시 기준

Living City v0.1은 다음 조건을 만족했을 때 첫 번째 완성 버전으로 본다.

1. 100명의 시민과 10개의 기업이 생성된다.
2. 시간이 진행되면 시민들이 자율적으로 경제활동을 수행한다.
3. 고용, 급여, 세금, 소비, 기업 매출이 하나의 경제 시스템으로 연결된다.
4. 정책 변경이 다음 시뮬레이션 상태에 반영된다.
5. 도시 맵에서 시민과 건물을 선택하고 관찰할 수 있다.
6. REST와 SSE를 통해 서버 상태가 정확히 반영된다.
7. 서버 재시작과 SSE 연결 해제 이후 정상 복구가 가능하다.
8. 동일한 시드와 실행 조건으로 결과를 재현할 수 있다.
9. 시뮬레이션 중 자금 정합성이 유지된다.
10. 장시간 실행 시 메모리와 처리 시간이 비정상적으로 증가하지 않는다.
